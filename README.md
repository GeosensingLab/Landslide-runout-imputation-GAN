# Landslide Runout Distance Estimation Using Ensemble Imputation and GAN Regression

This repository contains the Jupyter notebooks used to develop the computational framework described in **"Landslide runout distance estimation using ensemble imputation and GAN regression"** by Lin Li, Haoyu Liu, Guangshuai Wang, Hui Wang, and Weibing Gong.

The workflow links two stages: (1) reconstruction of missing geometric attributes in landslide inventories through category-specific ensemble imputation, and (2) estimation of landslide runout distances using generative adversarial network (GAN)-based regression. It considers three triggering categories (earthquake, rainfall, other factors) and three material categories (soil, rock, mixed materials).

## Workflow

```text
Raw landslide inventory CSV with geometry and observed L(m)
                         |
                         v
      Category-specific preprocessing and screening
                         |
                         v
             Ensemble missing-data imputation
                         |
                         v
      Reconstruction evaluation and completed features
                         |
                         v
       Restore observed runout-distance column L(m)
                         |
                         v
            Category-specific GAN regression
                         |
                         v
           Prediction CSV + diagnostic figure
```

The imputation notebooks implement combinations of K-nearest neighbors, iterative regression, tree-based estimators, targeted feature-wise regression, and variational autoencoders (VAEs). The GAN regression notebook implements a supervised generator/discriminator training setup and supports ensemble prediction. The exact imputation configuration differs among landslide categories.

## Requirements and installation

The imported Python packages are:

* `numpy`, `pandas`, `scipy`, `scikit-learn` for numerical processing, imputation, and evaluation;
* `tensorflow` (including Keras) for the VAE-based imputation components;
* `torch` for GAN-based regression;
* `matplotlib` for regression visualizations;
* `jupyterlab` or Jupyter Notebook to execute the `.ipynb` files.

Create an isolated environment and install the packages:

```bash
python -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
python -m pip install jupyterlab numpy pandas scipy scikit-learn tensorflow torch matplotlib
jupyter lab
```

On Windows, activate with `.venv\\Scripts\\activate`. Install versions of TensorFlow and PyTorch appropriate to your operating system and accelerator. **No pinned software versions or validated environment file were supplied with these notebooks**; record tested package versions when preparing a formally reproducible release. CPU execution is possible, while some models can use a compatible GPU. The rock imputation notebook requests CPU execution for reproducibility.

## Required input data

Each imputation notebook reads its corresponding source CSV using a **relative path** such as `./Earthquake.csv`. The six required source CSVs are named in the table above. **They were not included among the seven supplied notebook files** and must be provided separately for a complete rerun.

The input CSVs must satisfy the following conditions:

1. Include a column named exactly **`L(m)`**, containing the measured landslide runout distance in meters.
2. Preserve original geometric variable names and units. Some feature-specific procedures use exact column names, including Unicode symbols and punctuation.
3. Use numeric or missing values for modeled geometric predictors; the notebooks attempt to remove nonnumeric metadata and identifier columns.
4. Preserve row identity and **row order**. In the second code cell, each imputation notebook appends the original `L(m)` column to the completed predictor table **by row position**, not by a record identifier.

Missing cells should use values recognized by pandas (for example, empty fields or `NaN`). To preserve correct pairings, verify that the output rows still align with the source inventory after preprocessing.

## How to run

### 1\. Run imputation for one category

Place the relevant raw CSV in the notebook's working directory (or update its `pd.read\_csv(...)` path). Open the matching category-specific imputation notebook and run its **two code cells in order**:

* **Cell 1:** load and preprocess the inventory; impute missing geometric entries; calculate reconstruction diagnostics; save intermediate CSV outputs.
* **Cell 2:** load the intermediate completed-features CSV; append the original observed `L(m)` values; save the final category-specific file required for GAN regression.

The exact output filename expected by the GAN code is given in the table. The second cell must finish successfully before the regression step.

### 2\. Run the corresponding GAN regression experiment

Open `Runout distance.ipynb` and run **only the code cell for the selected category** (see the cell order and file mapping above). That cell loads the previously generated category-specific CSV from the current working directory.

The supplied GAN experiment code performs the following operations:

* Uses `L(m)` as its target and the remaining attributes as predictors.
* Removes rows with residual missing values and handles outliers according to the selected options.
* Applies robust feature/target scaling and an 80% training / 20% validation split (`random\_state=42`).
* Trains a GAN regression model or an ensemble of GAN models, then reports prediction diagnostics.

The execution call at the end of each GAN cell currently specifies `outlier\_method='clip'`, `iqr\_multiplier=1.5`, and `use\_ensemble=True`. Under this configuration, the ensemble uses three individual regression models. The model architecture and training hyperparameters are defined in each cell.

**Do not use "Run All" in `Runout distance.ipynb` if you want separate saved results for all categories.** The six cells write identical filenames for their predictions and plots, and later cells overwrite earlier output files.

### 3\. Organize results

The notebooks write output files to the active working directory. For clear archiving, save the results of each category separately, for example:

```text
results/
  earthquake/
    train\_val\_predictions.csv
    gan\_outlier\_removal\_results.png
  rainfall/
    train\_val\_predictions.csv
    gan\_outlier\_removal\_results.png
  rock/
    train\_val\_predictions.csv
    gan\_outlier\_removal\_results.png
  ...
```

This `results/` layout is **recommended**, not automatically generated by the supplied code.

## Outputs

### Imputation outputs

Each imputation notebook saves a completed-feature CSV and evaluation summaries (including reconstruction measures). Several save observed-versus-predicted comparisons. The second cell generates the final category-specific CSV with the restored `L(m)` values, as listed in the table.

**Name collisions:** The Mixed and Others notebooks use the same filenames for their first-cell intermediate CSV outputs. Run them separately, or change their output paths to prevent one category from overwriting the other. The Soil notebook also writes feature comparison tables to its own output folder.

### GAN outputs

Each category-specific GAN code cell writes:

* `train\_val\_predictions.csv` -- training/validation predictions;
* `gan\_outlier\_removal\_results.png` -- diagnostic plots.

The supplied GAN notebook does not contain an explicit step to export trained network weights. Recreating trained models requires rerunning the corresponding experiment.
